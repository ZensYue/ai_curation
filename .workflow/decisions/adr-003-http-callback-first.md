# ADR-003：服务协作采用 HTTP + 回调主链路，轮询作补偿

## 结论

Java 主平台与 Python 爬虫服务之间，首期主链路采用 `HTTP + 回调`，轮询仅作为补偿和异常兜底机制。

## Why

爬虫任务执行时间不稳定，回调更适合作为主链路：

- 异步任务完成后可立即通知平台
- 实时性更好
- 平台端不需要持续高频查询
- 更符合任务完成时刻不确定的特点

轮询保留为补偿机制：

- 回调失败或丢失时可主动补查
- 适合处理长时间未返回、状态异常等情况
- 可作为任务巡检机制存在

因此结论不是二选一，而是“回调优先，轮询兜底”。

## 当前适用边界

本结论适用于：

- 平台与爬虫服务之间的异步任务协作
- 任务完成通知与状态补偿链路设计

## 何时重审

如果后续平台规模、吞吐量或时效要求显著变化，需要引入消息队列或事件流作为主链路时，再重审。
