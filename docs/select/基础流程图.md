### 技术流程说明

- 适合直接拆成 `n8n` 模块或子流程
- `数据清洗与标准化` 建议独立成层，不要和采集逻辑混写
- `潜力筛选` 与 `利润核算` 分开，便于后续单独调规则
- `Vika` 建议按多表回写，后续再视情况汇总成一个主看板
- `监控与告警` 既处理流程失败，也处理业务异常

## 用户流程图

```mermaid
flowchart TD
  A["开始一天的选品工作"] --> B["查看今日同步结果"]
  B --> C["确认哪些产品已抓取完成"]
  C --> D["查看系统推荐的候选品"]
  D --> D1["热卖产品"]
  D --> D2["潜力产品"]
  D --> D3["利润可做产品"]

  D1 --> E["人工确认重点商品"]
  D2 --> E
  D3 --> E
  E --> F["补充必要资料"]
  F --> F1["品牌 / 型号是否正确"]
  F --> F2["是否需要手工修正分类"]
  F --> F3["是否补充国内采购价"]
  F --> F4["是否补充本地最低价"]
  F --> G["查看利润和风险提示"]
  G --> H["筛选可继续跟进的商品"]
  H --> H1["保留"]
  H --> H2["观察"]
  H --> H3["排除"]

  H1 --> I["更新跟进状态"]
  H2 --> I
  H3 --> I
  I --> J["查看异常和缺失项"]
  J --> K["等待下一轮自动同步"]
```

### 用户流程说明

- 用户版只保留业务操作，不展示接口、字段和公式
- 主线是：`看结果 -> 确认 -> 补资料 -> 看利润 -> 做决策`
- 首期状态建议只保留 `保留 / 观察 / 排除` 三档
- 需要让用户快速知道哪些商品存在信息缺失或需要人工补录
- 适合给业务负责人、运营人员、项目使用者查看
