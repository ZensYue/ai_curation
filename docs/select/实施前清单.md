# 实施前清单

## 说明

在开始实施 `n8n KP 平台电子产品自动选品项目` 前，建议先补齐以下资料并确认关键问题。否则流程虽然可以搭建，但会在抓取方式、字段映射、业务规则和成本计算上反复返工。

## 一、需提供的资料

### 1. 平台与账号资料

- `KP` 平台名称、网址、登录方式、是否有 API
- `Vika` 的 `API Token`、空间信息、目标表信息、是否已建表
- 国内平台可用方式：`API`、网页抓取、榜单页或搜索页
- 欧洲平台首批名单及访问入口
- 汇率接口来源
- `ePonuda` 或其他塞尔维亚比价网站的入口与可用方式

### 2. 数据源清单

- KP 热卖榜入口 URL
- 欧洲热卖平台 URL
- 国内热卖榜 URL
- 新品监控来源
- 每个平台的目标类目范围

建议新品监控来源至少明确：

- 品牌官网
- 科技媒体
- RSS 源

### 3. Vika 表结构资料

- 每张表最终名称
- 每张表字段名
- 字段类型
- 唯一键规则
- 更新策略
- 是否需要主看板汇总表

更新策略建议至少明确：

- 覆盖更新
- 追加历史

### 4. 商品标准化资料

- 品类字典
- 品牌别名映射
- 型号命名规则
- 去重规则

建议首期标准品类：

- 手机
- 大相机
- 小相机 / 运动相机
- 电脑设备
- 配件
- 其他电子产品

### 5. 业务判定规则

- 热卖前 `50` 的具体榜单定义
- 浏览量、收藏数、销量、评价增量的可获取性
- “热门关注商品”判定阈值
- “可降价切入商品”判定阈值
- “增量商品”判定阈值
- “蓝海产品”判定阈值
- 最低利润额 / 利润率门槛

### 6. 成本与物流资料

- 国内采购成本取值规则
- 头程参数是否固定
- 尾程费用规则是否按文档默认表
- 是否有特殊品类附加费
- 汇率刷新频率

文档中的默认参数如下：

- 空运单价：`69 RMB/KG`
- 体积重基数：`6000`
- 最低计费重：`12KG`

### 7. 环境与风控资料

- 是否已有当地代理 IP
- 是否允许浏览器自动化
- 是否需要验证码处理
- n8n 运行环境
- 告警渠道

建议明确的运行环境：

- 本地
- 云端
- Docker

建议明确的告警渠道：

- Telegram
- 邮件
- 飞书 / 钉钉

## 二、待确认问题

### 1. 数据源与抓取方式

- `KP` 平台是否只能网页抓取？
- KP 的热卖榜到底按什么维度获取？
- 欧洲首批做哪些国家、哪些站点？
- 国内平台价格抓取用什么口径？
- 新品监控首期做哪些固定来源？

### 2. 商品标准化与映射

- 型号标准化是靠规则表、AI，还是两者结合？
- “品牌一致 + 型号一致” 是否足够作为去重规则？
- 颜色、容量、套餐是否算同款？
- 如果平台标题混乱，是否允许人工维护映射表？

### 3. 业务规则与判定标准

- 浏览量、收藏数、近 7 天新增评价是否都能拿到？
- 拿不到时是否允许用替代指标？
- “蓝海产品”中的 “KP 供应稀缺 / 热度不高” 如何定义？
- 最低利润额和利润率门槛是多少？
- 哪些商品类型需要直接剔除？

### 4. 成本、汇率与本地比价

- 国内采购成本按标价、到手价还是最低采购价？
- `ePonuda` 搜不到商品时是否继续利润核算？
- 尾程费用是否按国家拆分？
- 汇率取实时值、每日值还是人工维护值？

### 5. 数据回写与业务使用

- `Vika` 是多表管理，还是主表 + 明细表？
- 是否需要人工确认状态字段？
- 候选品跟进状态是否先只保留三档？
- 是否需要保留抓取历史和利润历史？

## 三、建议先固定的表

首期建议至少建设以下数据表：

1. `KP平台产品热卖信息`
2. `周边国家热卖产品信息`
3. `国内产品热卖信息`
4. `国内新发布产品信息`
5. `有潜力产品信息表`
6. `选品利润核算表`

另外建议增加两张基础规则表：

1. `商品映射规则表`
2. `全局参数表`

## 四、建议实施顺序

1. 先确认平台与账号资料
2. 先定 `Vika` 表结构
3. 再定商品标准化与去重规则
4. 再定潜力筛选阈值
5. 再定利润核算参数
6. 最后开始拆 `n8n` 流程并实施
